En este capítulo, se presentaron muchas reglas para declarar métodos y variables. Los métodos comienzan con modificadores de acceso y especificadores opcionales en cualquier orden (aunque comúnmente con los modificadores de acceso primero). Los modificadores de acceso que se discutieron en este capítulo son `private`, paquete (omitido), `protected` y `public`. El especificador opcional para métodos que se cubrió en este capítulo es `static`. Se cubrirán modificadores de métodos adicionales en capítulos futuros.

A continuación viene el tipo de retorno del método, que es `void` si no hay valor de retorno. El nombre del método y la lista de parámetros se proporcionan después, los cuales componen la firma única del método. El nombre del método utiliza las reglas estándar de identificadores de Java, mientras que la lista de parámetros está compuesta por cero o más tipos con nombres. También se puede añadir una lista opcional de excepciones a continuación de la lista de parámetros. Finalmente, un bloque define el cuerpo del método (que se omite para los métodos abstractos).

Los modificadores de acceso se utilizan para mucho más que solo métodos, por lo que hay que asegurarse de comprenderlos bien. Usar la palabra clave `private` significa que el código solo está disponible desde dentro de la misma clase. El acceso de paquete (_package access_) significa que el código está disponible solo desde dentro del mismo paquete. Usar la palabra clave `protected` significa que el código está disponible desde el mismo paquete o subclases. Usar la palabra clave `public` significa que el código está disponible desde cualquier lugar.

Tanto los métodos estáticos como las variables estáticas son compartidos por todas las instancias de la clase. Cuando se referencian desde fuera de la clase, se llaman utilizando el nombre de la clase; por ejemplo, `Pigeon.fly()`. A los miembros de instancia se les permite llamar a miembros estáticos, pero a los miembros estáticos **no** se les permite llamar a miembros de instancia. Además, las importaciones estáticas (_static imports_) se utilizan para importar miembros estáticos.

También se presentó el modificador `final` y se mostró cómo se puede aplicar a variables locales, de instancia y estáticas. Recuerde, una variable local es efectivamente final (_effectively final_) si no se modifica después de ser asignada. Una prueba rápida para esto es añadir el modificador `final` y ver si el código aún compila.

Java utiliza el **paso por valor** (_pass-by-value_), lo que significa que las llamadas a los métodos crean una copia de los parámetros. Asignar nuevos valores a esos parámetros dentro del método no afecta a las variables del invocador. Sin embargo, llamar a métodos sobre objetos que son parámetros de método cambia el estado de esos objetos y sí se refleja en el invocador. Java soporta el _autoboxing_ y _unboxing_ de primitivos y clases envolventes (_wrappers_) automáticamente dentro de un método y a través de llamadas a métodos.

Los métodos sobrecargados (_overloaded methods_) son métodos con el mismo nombre pero con una lista de parámetros diferente. Java llama al método más específico que puede encontrar. Se prefieren las coincidencias exactas, seguidas de primitivos más amplios (promoción). Después de eso viene el _autoboxing_ y finalmente los _varargs_.
