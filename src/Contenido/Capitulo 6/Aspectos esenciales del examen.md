**Se debe ser capaz** de escribir código que extienda otras clases. Una clase Java que extiende otra clase hereda todos sus métodos y variables `public` y `protected`. Si la clase está en el mismo paquete, también hereda todos los miembros de paquete (_package-private_) de la clase. Las clases que están marcadas como `final` no pueden ser extendidas. Finalmente, todas las clases en Java extienden de `java.lang.Object` ya sea directamente o desde una superclase.

**Se debe ser capaz** de distinguir y usar `this`, `this()`, `super` y `super()`. Para acceder a un miembro actual o heredado de una clase, **se puede usar** la referencia `this`. Para acceder a un miembro heredado, **se puede usar** la referencia `super`. La referencia `super` a menudo se utiliza para reducir la ambigüedad, como cuando una clase reutiliza el nombre de un método o variable heredada. Las llamadas a `this()` y `super()` se utilizan para acceder a constructores en la misma clase y en la clase padre, respectivamente.

**Se debe evaluar** el código que involucra constructores. La primera línea de cada constructor es una llamada a otro constructor dentro de la clase usando `this()` o una llamada a un constructor de la clase padre usando la llamada `super()`. El compilador insertará una llamada a `super()` si no se declara ninguna llamada a un constructor. Si la clase padre no contiene un constructor sin argumentos (_no-argument constructor_), **se debe proporcionar** una llamada explícita al constructor padre. **Se debe ser capaz** de reconocer cuándo se proporciona el constructor por defecto (_default constructor_). **Se debe recordar** que el orden de inicialización consiste en inicializar todas las clases en la jerarquía de clases, comenzando con la superclase. Luego se inicializan las instancias, nuevamente comenzando con la superclase. A todas las variables `final` **se les debe asignar** un valor exactamente una vez para cuando el constructor haya terminado.

**Se deben comprender** las reglas para la sobrescritura de métodos (_method overriding_). Java permite que los métodos sean sobrescritos, o reemplazados, por una subclase si se siguen ciertas reglas: un método debe tener la misma firma, ser al menos tan accesible como el método padre, no debe declarar ninguna excepción nueva o más amplia y debe usar tipos de retorno covariantes (_covariant return types_). Los métodos marcados como `final` no pueden ser sobrescritos ni ocultados.

**Se debe reconocer** la diferencia entre la **sobrescritura de métodos** (_method overriding_) y la **sobrecarga de métodos** (_method overloading_). Tanto la sobrecarga como la sobrescritura de métodos implican crear un nuevo método con el mismo nombre que un método existente. Cuando la firma del método es la misma, se le conoce como sobrescritura de métodos y debe seguir un conjunto específico de reglas de sobrescritura para compilar. Cuando la firma del método es diferente, con el método tomando diferentes entradas, se le conoce como sobrecarga de métodos, y ninguna de las reglas de sobrescritura es requerida. La sobrescritura de métodos es importante para el polimorfismo porque reemplaza todas las llamadas al método, incluso aquellas realizadas en una superclase.

**Se deben comprender** las reglas para ocultar métodos y variables (_method and variable hiding_). Cuando un método `static` se sobrescribe en una subclase, se le conoce como **ocultamiento de métodos** (_method hiding_). Del mismo modo, el **ocultamiento de variables** (_variable hiding_) es cuando un nombre de variable heredada se reutiliza en una subclase. En ambas situaciones, el método o variable original aún existe y es accesible dependiendo de dónde se acceda y el tipo de referencia utilizado. Para el ocultamiento de métodos, el uso de `static` en la declaración del método debe ser el mismo entre la clase padre y la hija. Finalmente, el ocultamiento de variables y métodos generalmente **se debe evitar** ya que conduce a código confuso y difícil de seguir.

**Se debe ser capaz** de escribir código que cree y extienda clases abstractas. En Java, las clases y los métodos pueden ser declarados como `abstract`. Una clase abstracta no puede ser instanciada. Una instancia de una clase abstracta se puede obtener solo a través de una subclase concreta. Las clases abstractas pueden incluir cualquier cantidad de métodos abstractos y no abstractos, incluyendo cero. Los métodos abstractos siguen todas las reglas de sobrescritura de métodos y solo pueden ser definidos dentro de clases abstractas. La primera subclase concreta de una clase abstracta debe implementar todos los métodos heredados. Las clases y métodos abstractos no pueden ser marcados como `final`.

**Se deben crear** objetos inmutables. Un objeto inmutable es aquel que no puede ser modificado después de ser declarado. Una clase inmutable se implementa comúnmente con un constructor `private`, sin métodos _setter_ y sin la capacidad de modificar objetos mutables contenidos dentro de la clase.
