Este capítulo **ha presentado** los hilos de plataforma y los virtuales y **ha descrito** algunos de los conceptos clave de concurrencia que **se necesita** conocer para el examen (¡y para ser un mejor desarrollador de software!). **Se debe** saber **crear** y **definir** el trabajo de un hilo mediante una instancia de `Runnable`. Con la API de concurrencia, además, **se debe** saber **crear** hilos con expresiones lambda `Callable`.

A estas alturas, **se debe** saber **ejecutar** tareas de forma concurrente con `ExecutorService` como todo un profesional. También **se debe** conocer qué instancias hay disponibles, incluidos los servicios programados y los de grupo de hilos (_thread pool_).

La seguridad de hilos consiste en **proteger** los datos para que no **se corrompan** cuando varios hilos los modifican al mismo tiempo. Java **ofrece** muchas herramientas para **mantener** los datos seguros, entre ellas las clases atómicas, los métodos y bloques `synchronized`, el marco `Lock` y `CyclicBarrier`. La API de concurrencia **incluye** además numerosas clases de colecciones que **gestionan** por ti el acceso multihilo. **Hay que conocer** las colecciones concurrentes, incluidas las clases `CopyOnWrite`, que **crean** una nueva estructura subyacente cada vez que **se modifica** la colección.

Al **procesar** tareas de forma concurrente, **pueden surgir** diversos problemas de hilos. El interbloqueo (_deadlock_), la inanición (_starvation_) y el bloqueo vivo (_livelock_) **pueden** dar lugar a programas que parecen atascados, mientras que las condiciones de carrera (_race condition_) **pueden** producir datos impredecibles. Para el examen, **basta con conocer** la teoría básica de estos conceptos. En el desarrollo profesional de software, sin embargo, **encontrar** y **resolver** estos problemas **es** una habilidad valiosa.

Por último, **se han** tratado los streams paralelos y **se ha** mostrado cómo **usarlos** para **realizar** descomposiciones y reducciones paralelas. Los streams paralelos **pueden** mejorar mucho el rendimiento de la aplicación, pero también **pueden** provocar resultados inesperados, ya que el procesamiento deja de estar ordenado. **Hay que recordar evitar** las expresiones lambda con estado, sobre todo con streams paralelos.
