El sistema de módulos de la plataforma Java **organiza** el código a un nivel superior a los paquetes. Cada módulo contiene uno o más paquetes y un archivo `module-info.java`. El módulo `java.base` es el más común y **se suministra** automáticamente a todos los módulos como dependencia.

El proceso de compilación y ejecución de módulos usa `--module-path`, también conocido como `-p`. Para **ejecutar** un módulo se usa la opción `--module`, también conocida como `-m`. La clase que se va a ejecutar **se especifica** en el formato `moduleName/className`.

El archivo de declaración de módulo admite varias directivas. La directiva `exports` **especifica** que un paquete debe ser accesible fuera del módulo. Opcionalmente, **puede restringir** esa exportación a un módulo concreto. La directiva `requires` **se usa** cuando un módulo depende de código de otro módulo. Además, `requires transitive` **puede usarse** cuando todos los módulos que requieren uno siempre **deban** requerir otro. Las directivas `provides` y `uses` **se usan** al compartir y consumir un servicio. Por último, la directiva `opens` **se usa** para **permitir** el acceso mediante reflexión.

Tanto el comando `java` como `jar` **pueden usarse** para **describir** el contenido de un módulo. El comando `java` **puede**, además, **listar** los módulos disponibles y **mostrar** la resolución de módulos. El comando `jdeps` **imprime** información sobre los paquetes utilizados, además de la información a nivel de módulo. El comando `jmod` **se usa** cuando se trabaja con archivos que no cumplen los requisitos de un JAR. El comando `jlink` **crea** una imagen de tiempo de ejecución de Java más pequeña. El comando `jpackage` **crea** una imagen de aplicación, que es un archivo autocontenido y específico del sistema operativo.

Hay tres tipos de módulos. Los módulos nombrados (_named modules_) contienen un archivo `module-info.java` y están en el module path. Solo **pueden leer** desde el module path. Los módulos automáticos (_automatic modules_) también están en el module path pero aún no **se han** modularizado. Pueden tener un nombre de módulo automático establecido en el manifiesto. Los módulos sin nombre (_unnamed modules_) están en el classpath.

Las dos estrategias de migración más comunes son la migración de arriba abajo (_top-down_) y la de abajo arriba (_bottom-up_). La migración de arriba abajo **comienza** migrando el módulo con más dependencias y **coloca** todos los demás módulos en el module path. La migración de abajo arriba **comienza** migrando un módulo sin dependencias y **mueve** un módulo al module path cada vez. Ambas estrategias **requieren asegurarse** de que no haya dependencias cíclicas, ya que el sistema de módulos de la plataforma Java no **permite** que las dependencias cíclicas se compilen.
